Pruebas de rutinas

Las rutinas sistémicas desde el Admin y el Entrenador: listado y búsqueda, alta y edición con sus circuitos en orden, el ida y vuelta con el editor de circuitos, la baja lógica y la reactivación, y las rutinas puntuales de un alumno: asignarlas para un día, desde la rutina o desde el alumno, y quitarlas. Cada caso dice cómo probarlo y qué tenés que ver. Marcá el resultado y anotá lo que observes.

Entornos

Local

Backend local en localhost:3000 y el front con npm run dev. Hace falta para los casos con el servidor apagado.

Render

powerapp-web.onrender.com contra el backend de Render. Todo lo que crees queda en esa base.

Cualquiera

El caso da lo mismo en los dos. Desde T44 el front no tiene mocks: todo va al backend real.

Cuentas y datos

  • Una cuenta admin real y una de entrenador. Las de demo ya no existen.
  • Todo lo que crees, con el prefijo «QA»: , y el circuito .
  • Los circuitos del seed, solo para agregar. Editar un circuito cambia todas las rutinas que lo usan: los casos que editan o duplican usan QA Circuito rutina.
  • Las rutinas no se pueden borrar, solo dar de baja. FIN-01 deja las de prueba dadas de baja.
  • Un alumno de prueba nuevo para asignar y quitar rutinas puntuales, registrado desde /registro: , con un email tuyo con sufijo, por ejemplo . Las asignaciones que el alumno entrenó no se pueden quitar.
  • Dos roles a la vez: ventana normal para el admin o el entrenador y de incógnito para el alumno.

Cómo encararlo

  • Seguí el orden de la página. QA Rutina A se crea en CRE-01 y la usan los casos siguientes.
  • DevTools › Network, filtrado por routine, para ver qué requests salen, con qué body y qué código responden.
  • Dos pestañas para EDT-05, EDT-06, ASG-07, QUI-04 y QUI-05: en una dejás la pantalla abierta y en la otra cambiás algo.
  • Lo que hoy falla está marcado con un aviso amarillo: un enlace con un id que no es un UUID muestra un error genérico (EDT-04), y lo que confirman asignar y quitar una rutina puntual no dice cuál (ASG-02 y QUI-03). Los tres los arregla el PR #70 (T51), que todavía no está en develop.
