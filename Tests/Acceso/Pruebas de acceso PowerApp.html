Entornos

Local

Backend local en localhost:3000 y el front con npm run dev y VITE_USE_MOCKS=false. Todo es real, y la contraseña temporal sale en la consola del backend.

Demo

npm run dev con VITE_USE_MOCKS=true, o el sitio de Render, que hoy tiene los mocks prendidos. Sirve para el cambio obligatorio de contraseña, que con cuentas reales todavía no se activa (B9).

Render

powerapp-web.onrender.com contra el backend de Render, con cuentas reales. Es la prueba de punta a punta: el login real desde el sitio publicado nunca se probó.

Qué tenés que tener a mano

  • Una cuenta real de cada rol, de las del seed. Admin y entrenador no se pueden crear desde el registro.
  • La contraseña temporal: el backend todavía no manda mails (C4). En local aparece en su consola como [EMAIL STUB] Contraseña temporal para …. En Render, en los Logs del servicio del backend.
  • DevTools: en Network, filtrá por users para ver qué requests salen. En Application › Local Storage, la clave powerapp.session es la sesión. Para simular que no hay conexión, Network › Offline.
  • Orden sugerido: Registro, Login, Recuperar, Cambio obligatorio, Cambio voluntario, Cerrar sesión y Navegación. REC-01 te da la temporal que usan LOG-10, REC-06, REC-07, REC-08 y CPO-08.
  • Lo que se sabe que hoy falla está marcado en cada caso con un aviso amarillo (LOG-10 y REC-09 por el backend, NAV-07 por el front). Marcalos igual: así queda registrado cuándo se arreglan.
