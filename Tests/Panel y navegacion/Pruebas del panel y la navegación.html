Entornos

Local

Backend local en localhost:3000 y el front con npm run dev. Hace falta para el panel con el servidor apagado.

Render

powerapp-web.onrender.com contra el backend de Render. Es el único donde el servidor se duerme de verdad (SRV-01).

Cualquiera

El caso da lo mismo en los dos. Con cuentas reales, los mocks no intervienen aunque estén prendidos.

Cuentas y datos

  • Una cuenta real de cada rol: alumno, entrenador y admin. Las de demo no sirven: el backend rechaza su token.
  • Un alumno de prueba nuevo para SES-02, que le cierra la cuenta: , con un email tuyo con sufijo, por ejemplo .
  • Para ver los dos diseños, DevTools a 390 px (celular, con tab bar) y la ventana a más de 960 px (escritorio, con barra lateral).
  • Dos roles a la vez: ventana normal y ventana de incógnito.

Cómo encararlo

  • Ya están en «Pruebas de acceso» y acá no se repiten: rutas sin sesión, «/», el rol equivocado en el inicio de otro rol, /cualquier-cosa, la sesión vencida al abrir Datos personales y la cuenta cerrada con la sesión abierta (NAV-01 a NAV-07, OUT-03, OUT-04 y LOG-13). El catálogo y cómo se llega a cada sección están en el plan de cada sección.
  • DevTools › Network sirve para tres cosas: ver los requests, bloquear uno (clic derecho › Block request URL) y simular un servidor lento (Throttling › Add custom profile con 5000 ms de latencia).
  • Local Storage (DevTools › Application) guarda la sesión en powerapp.session. SES-01 le cambia el token.
  • Lo que hoy falla está marcado con un aviso amarillo: el inicio del alumno sigue en construcción (T38).
